# 架构与取舍

## 三条入口，共用执行引擎

React 面板负责测试文件、步骤编排与结果浏览，Electron 主进程负责窗口、IPC、工作区和可见浏览器。HTTP/MCP 入口面向外部工具。它们最终复用 `runtime`，而不是分别维护自动化逻辑。

`RunSession` 可接受外部 Playwright page，此时不拥有浏览器；无头模式自行拥有 context，必要时在会话范围复用 browser。这样既能复用用户当前操作的页面，也能让测试会话隔离 Cookie 和页面状态。单个可见页面的交互通道串行，多浏览器会话的并行由单机资源约束。

## 为什么用测试文件，而不只提供 click API

测试文件提供需求级元信息、多个 case、setup/teardown、fixture、宏和显式断言。预检在浏览器启动前检查结构、引用和弱断言。运行目标通过 origins、credentialRef、vars 在调用时传入，不把特定环境绑定到文件中。

## 期限与取消

页面探测、单步、run 和 session 使用不同期限，避免一个无返回的 page.evaluate 阻塞整个会话。异步调用先返回 session 句柄，随后通过事件或轮询获取终态。合作式取消优先让执行器保存已有证据；可选子进程隔离用于终止不合作的执行。

展示版修正了期限计时器生命周期：调用方正在等待的期限需要维持 Node 事件循环，完成或放弃后必须清除。不能仅用 unref 避免进程存活，也不能让已经取消的会话留下长时间计时器。

## 证据与断言的关系

截图表明发生了什么，显式断言才定义通过标准。报告分离动作、校验项和失败类别；证据包记录产物与摘要。演示使用真实浏览器执行正例和故意错误的值断言，并校验证据包。

本地自检覆盖页面实际抛错、陈旧构建、文件内容/图像截断、多个入口不一致和弱断言。夹具全部使用合成数据，其目的在于验证缺陷检出机制，而非复现组织内部业务。

## 仍保留的工程取舍

- 文件系统适合本地、可搬运的工作区；大量历史查询和多用户协作需要额外索引与权限层。
- 页面注入降低引擎分叉，也增加所有权、取消与浏览器生命周期的处理成本。
- DOM/testid 优先，OCR 为回退路径；视觉识别不会替代明确的业务断言。
- 模块化 runtime 与桌面 UI 已分离，但 Electron main 仍偏大，可继续按服务职责拆分。
